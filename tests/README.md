# 测试覆盖说明

运行：`uv run pytest -v`，日志按「业务域 → 用例类 → 用例」三级展示，
可直接看出每个业务覆盖了哪些场景。

| 测试文件 | 业务域 | 覆盖场景 |
| --- | --- | --- |
| `tests/test_metrics.py` | 请求级指标与链路标识 | 同一 request_id 重复上报幂等、重复上报不污染耗时/错误口径、不同 ID 全部计数；采样关闭期间丢弃、关闭期间的 ID 不污染开启后计数、切换不回溯；200 并发唯一 ID 无丢失、64 线程同一 ID 恰有一个获胜 |
| `tests/test_alerts.py` | 时间窗口告警 | 首次越界只告警一次、不越界不告警；PENDING→FIRING 升级时机、未持续静默清除、FIRING 逐级升级且始终只有一条；收敛、cooldown 内静默 reopen、超 cooldown 新告警；64 线程并发越界只有一条 FIRING、多规则并发互不漏报 |
| `tests/test_rules.py` | 规则热更新与降级 | 5 类校验失败原因码可区分、非对象/非数组载荷；好规则生效 + 坏规则隔离、重名规则拒绝；整批失败保留上一版（版本号不变）；10 次热更新与 100 次上报并发，版本严格 +1、样本零丢失 |
| `tests/test_api.py` | HTTP 端到端 | 上报幂等与指标口径、X-Request-ID 透传、/api/demo 自动埋点；告警可见、非法 state 400；部分坏规则 200 带 rejected、整批坏 422 且旧版保留 |
| `tests/test_tracing.py` | 链路标识中间件 | 客户端 ID 沿用并回写、缺失自动生成且每次不同、空白头视为缺失 |
